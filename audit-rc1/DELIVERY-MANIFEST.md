## PDF Arabic text layer — limitation, stated explicitly

Checked with `tools/audit/pdf-text-probe.py`, which parses the PDFs' ToUnicode
CMaps and decodes the page content streams with the standard library only. No
production code was modified and the PDFs were not re-exported or rasterised.

**The v1.2.0 failure mode is absent.** The five PDFs carry eight embedded
Type0 / Identity-H subset fonts, each with a ToUnicode CMap. Extraction yields
**0 unmapped characters** and **no Latin-glyph substitution**; the bytes are
valid UTF-8 Arabic.

**A different limitation is present, and it matters for this audit.** The text
layer stores Arabic as **presentation forms in visual (reversed) order**, not as
base letters in logical order:

| Report | Pages | Extracted chars | Arabic base letters | Arabic presentation forms | % presentation | Unmapped | Literal search for `متوسط القيم` |
|---|---|---|---|---|---|---|---|
| session-S1-mixed | 25 | 27,588 | 3,990 | 13,711 | 77.5% | 0 | **0 hits** |
| session-S2-mixed | 25 | 27,619 | 4,055 | 13,625 | 77.1% | 0 | **0 hits** |
| session-S3-mixed | 26 | 27,730 | 3,993 | 13,800 | 77.6% | 0 | **0 hits** |
| session-S4-mixed | 26 | 27,627 | 4,069 | 13,584 | 77.0% | 0 | **0 hits** |
| session-S5-hard | 26 | 30,420 | 4,294 | 14,865 | 77.6% | 0 | **0 hits** |

Extracted sample (S1 cover): `دﺪﺠﺘﻣ يدﺪﻋ ﺐﻳرﺪﺗ ﺮﻳﺮﻘﺗ` — which is
`تقرير تدريب عددي متجدد` reversed and written in isolated/medial/final forms.

Consequence for the reviewer: the PDFs are **correct on screen and correct in
print**, but their text layer **cannot be searched against the source strings and
cannot be used to judge number–noun agreement, singular/dual/plural, or RTL
integrity** — the letters have already been shaped and reordered by the renderer.

Per the delivery instruction, production code was **not** modified to address
this. The frozen PDFs are delivered unchanged, and the supplemental plain-text
renderings below are provided **in addition to**, never in place of, the PDF and
JSONL artifacts.

## Blind-audit JSONL — what is frozen and what is derived

`blind-audit-250.jsonl` (and the five per-session splits) carry one record per
question. Each record holds:

- **`frozen_question`** — the frozen RC1 question object, verbatim. Verified
  byte-for-byte against `audit-rc1/audit-sample.jsonl`: **250 / 250 identical**,
  with options, option order, published key and correct value preserved
  **250 / 250**.
- Flat reviewer-facing fields lifted from it unchanged: `sessionId`,
  `questionNumber`, `family`, `templateId`, `difficulty`, `askedUnknown`,
  `reasoningDirection`, `stem`, `options`, `publishedKey`,
  `publishedCorrectValue`, `explanation` (incl. `quickMethod` and `reminder`),
  `optionFeedback`, `distractorProvenance` (per-option `misconceptionId` and
  `derivation`), `fingerprint`, `validationMetadata`, `complexity`,
  `numericRank`, `feasibleRankRange`, and `generation` (question id, seed,
  generator id, engine version, and the exact call needed to reproduce it).
- **`audit.params`** — the parameter object the production solver consumed, read
  from the frozen output and independently cross-checked against a rebuild of the
  candidate from its recorded seed. **250 / 250 matched; 0 divergences.** Not
  reconstructed by hand.
- **`audit.oracleResult`** — the independent oracle re-run over the published
  statement, then the post-shuffle locate-and-compare: the oracle's answer, which
  displayed letters carry it, whether exactly one does, whether that letter is
  the published key, `postShuffleKeyMismatch`, and a PASS/FAIL verdict.
  **250 PASS / 0 FAIL.**
- **`audit.arabicFlag`** — the known-defect detector
  (`AR_DEFINITE_PLURAL_BARE_NUMERAL`, `SIGNOFF_RC1.md §8`) run over the frozen
  text. **13 questions flagged, all 13 in the stem** — the same 13 reported in
  the sign-off. The flag marks and cites; it changed no generation, no
  validation, no option order, no key, no explanation, and removed nothing.
